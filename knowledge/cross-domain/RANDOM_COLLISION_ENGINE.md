# DC//LAB Random Collision Engine

This mode deliberately reverses the usual concept-first process.

The purpose is to escape local creative habits by letting **unrelated technical systems collide before an artistic meaning is assigned**.

This is not random styling. It is a search procedure for discovering behavior that we would not have designed directly.

Use it when the current body of work feels repetitive, over-rationalized or trapped inside one implementation vocabulary.

---

## 1. Two creative modes

DC//LAB now has two valid starting modes.

### Intent-first

Use when there is already a strong artistic question, message, material or interaction premise.

`intention -> representations -> implementation candidates -> prototype -> refinement`

### Collision-first

Use when exploration itself is the goal.

`blind draw -> coupled prototype -> observe -> interpret -> art-direct -> mutate`

Neither mode is superior. The failure is pretending to use a broad knowledge library while repeatedly selecting the same familiar mechanisms.

---

## 2. Blind draw

Do not name the artwork first.
Do not choose a message first.
Do not choose typography just because DC//LAB already has type-heavy work.

For each experimental seed, randomly draw:

```text
1 carrier/material
+ 2 representation families that are technically distant
+ 2 transformation operators
+ 1 temporal model
+ 1 interaction consequence
+ 1 severe design constraint
```

Optional extra draw:

```text
+ 1 rendering/material treatment
+ 1 secondary sensor/driver
```

The random seed must be recorded so the draw is reproducible.

---

## 3. Distance constraints

Randomness alone can still create five versions of the same thing.

For a batch of five experiments:

- five different primary representations;
- at most two typography carriers;
- at most one project whose primary interaction is direct pointer displacement;
- at least one persistent framebuffer / feedback system;
- at least one population/agent/particle system;
- at least one discrete-rule system such as cellular automata, graph mutation or phase switching;
- at least one spatial/geometry system;
- no more than two projects sharing the same temporal model;
- at least one project should remain compelling without readable text.

If the draw violates batch diversity, redraw only the conflicting card.

---

## 4. Coupling rule

Do not merely stack the randomly drawn effects.

Weak collision:

`particles + reaction diffusion + glitch + text`

Strong collision:

`reaction-diffusion concentration becomes the velocity potential for particles; particle density locally changes reaction coefficients; the two systems alter each other`

Every selected major system must exchange data with at least one other system.

Useful shared currencies:

- position;
- velocity;
- density;
- distance;
- curvature;
- age;
- energy;
- color/luminance;
- connectivity;
- state index;
- pressure;
- time delay;
- occupancy;
- local entropy.

The collision becomes interesting when the systems negotiate rather than sit in layers.

---

## 5. Prototype before meaning

The first prototype is intentionally ugly.

Do not spend time on final typography, palette, framing or explanatory text.

Implement enough to answer:

```text
What surprising behavior appears?
What does the system keep doing when left alone?
What does it resist?
What does it amplify?
Where does instability become beautiful?
What states feel dead?
What states feel dangerous / fragile / massive / intimate / biological / mechanical / social?
```

Run it for long enough to see delayed behavior.

Capture several states, not one hero frame.

---

## 6. Emergence harvest

After the raw prototype exists, write observations without forcing a narrative.

Example:

```text
OBSERVED
- connected regions slowly starve isolated regions
- user cuts create delayed collapse elsewhere
- regeneration occurs from edges, not centres
- dense zones look architectural
- sparse zones feel biological
```

Only then ask what this behavior could mean artistically.

Possible readings of the exact same mechanics might be:

- censorship;
- urban growth;
- memory;
- social contagion;
- erosion;
- attention;
- migration;
- collective intelligence;
- supply chains;
- language;
- repair;
- grief;
- desire;
- ecological succession.

Meaning is selected because it amplifies behavior already present in the prototype.

## 7. Artistic impact pass

Once a promising behavior exists, art direction starts.

Choose deliberately:

### Scale

- microscopic;
- bodily;
- architectural;
- planetary;
- diagrammatic.

### Composition

- poster hierarchy;
- fullscreen field;
- asymmetric void;
- edge crop;
- central mass;
- modular grid;
- anti-grid;
- spatial perspective.

### Material

- ink;
- light;
- smoke;
- glass;
- tissue;
- metal;
- dust;
- liquid;
- signal;
- paper;
- pixel/display artifact;
- synthetic organism.

### Color logic

Assign roles, not decoration.

Examples:

- alive / dormant;
- old / new;
- connected / isolated;
- stable / unstable;
- source / residue;
- attraction / repulsion.

### Typography

Only introduce type if it strengthens the behavior.

Possible roles:

- carrier;
- constraint;
- obstacle;
- force field;
- data source;
- annotation;
- residue;
- latent structure never directly rendered.

---

## 8. Interaction after emergence

The interaction should exploit what was discovered in the system.

Do not default to `cursor radius -> deformation`.

Possible viewer actions:

- cut links;
- seed organisms;
- freeze time locally;
- alter reaction chemistry;
- paint obstacles;
- invert polarity;
- introduce a predator;
- change topology;
- add/remove mass;
- change delay/history;
- redirect a flow field;
- switch a local material phase;
- move a boundary condition;
- create a permanent mutation.

The best interaction often changes **future behavior**, not only the current frame.

---

## 9. Mutation protocol

If a raw collision is weak, do not immediately discard everything.

Mutate one card at a time:

1. representation;
2. temporal model;
3. coupling relation;
4. constraint;
5. interaction consequence.

This makes it possible to learn why a collision failed.

After three mutations with no compelling behavior, kill the seed.

---

## 10. Anti-soup checks

Random collision has its own failure mode: technical soup.

Reject or simplify when:

- three effects are visible but do not influence one another;
- removing one system changes nothing important;
- complexity exists only in implementation, not behavior;
- the piece requires sliders to become visually interesting;
- the system has no recognizable state transitions;
- interaction only reveals the stack of effects;
- every frame looks like generic realtime VFX;
- a single tutorial reference dominates the surface appearance.

Randomness is used to generate **unexpected mechanisms**, not to excuse incoherence.

## 11. First blind draw — 2026-09-24

These were generated before assigning artistic meanings.
They are research seeds, not approved artworks.

### Collision A

```text
carrier: typography
primary: GPU particles / agents
secondary: instanced geometry
operators: sort/reorder + erode/dilate
 temporal: feedback memory
interaction: touch toggles topology
constraint: no noise
```

Post-draw hypothesis only: letter order could become a deterministic swarm topology that breaks and reconstructs from memory without any noise-driven motion.

### Collision B

```text
carrier: architectural cells
primary: vector field / advection
secondary: reaction-diffusion
operators: grow/decay + phase-shift
 temporal: coupled oscillators
interaction: touch seeds population
constraint: no smooth interpolation
```

Post-draw hypothesis only: abrupt chemical neighbourhoods could advect a rigid urban cellular structure, producing a city that switches between discrete metabolic regimes.

### Collision C

```text
carrier: line network
primary: Voronoi / Delaunay
secondary: optical/velocity field
operators: fold/mirror + feedback blur/sharpen
 temporal: birth/death
interaction: touch cuts links
constraint: horizontal attractor / baseline
```

Post-draw hypothesis only: a growing communication network whose links are born, sharpen into structure, then die when connectivity is cut.

### Collision D

```text
carrier: data-like symbols
primary: raster mask + morphology
secondary: procedural ribbons / mesh
operators: recursive transform + domain warp
 temporal: stochastic regime switching
interaction: dwell changes material
constraint: no smooth interpolation
```

Post-draw hypothesis only: flat symbols could periodically switch material state and extrude into ribbons, with abrupt rather than eased transitions.

### Collision E

```text
carrier: abstract symbols
primary: raymarched SDF geometry
secondary: cellular automaton
operators: collision + packing
 temporal: phase transition
interaction: dwell changes local phase
constraint: two colors only
```

Post-draw hypothesis only: packed volumetric organisms could inherit cellular states and physically change phase under sustained attention.

Do not promote any of these to artwork before a raw behavioral prototype exists.

## 12. Research rationale

This exploration mode is informed by examples where simple systems are deliberately combined into richer hybrid mechanisms:

- reaction-diffusion and cellular automata reused as drivers for particles and geometry;
- feedback loops used as persistent state rather than post-processing only;
- SDF geometry coupled to interactive particle systems;
- quadtree structures feeding Voronoi systems;
- particle systems coupled with soft-body constraints and body sensing;
- generative studio systems built as evolving visual languages rather than fixed effects.
