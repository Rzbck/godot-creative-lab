# Graphic Design Atlas for DC//LAB

This atlas collects visual-system principles that should inform realtime sketches, posters, installations, motion identities and future A/B/C live-compositing tools.

## 1. Hierarchy before decoration

A strong composition tells the eye where to go first, second and third.

Hierarchy can be created with:

- scale
- contrast
- position
- density
- whitespace
- color
- type weight
- motion
- focus/sharpness
- repetition

### Realtime translation

Decide which layer owns attention. Background motion should not compete equally with the primary typographic or interactive event.

## 2. Figure / ground

The viewer constantly separates subject from background.

### Realtime opportunities

- invert figure and ground interactively;
- let negative space become the active shape;
- use masks where the background reveals the typography;
- design transitions that exchange foreground/background roles.

## 3. Negative space

Empty space is a compositional material.

### Rule

Do not fill every region because a shader can. Preserve breathing room and intentional silence.

## 4. Alignment

Alignment creates invisible connections between elements.

Useful systems:

- edge alignment
- center alignment
- baseline alignment
- axis alignment
- grid alignment
- optical alignment

### Realtime rule

Animated elements can leave the grid temporarily, but should do so as an authored event rather than from numeric drift.

## 5. Proximity

Elements close together are perceived as related.

### Realtime use

Proximity can become semantic: related items attract, unrelated layers repel, clusters represent categories or beats.

## 6. Similarity

Color, shape, scale, motion and type treatment create perceived families.

### Live-system use

A/B/C decks can each own a family signature while sharing one global visual language.

## 7. Repetition

Repetition creates rhythm and identity.

### Realtime forms

- repeated glyphs
- modular tiles
- pulses
- recurring transition gestures
- repeated proportions
- color recurrence

Variation should occur against a recognizable repeated system.

## 8. Rhythm

Rhythm exists spatially and temporally.

### Spatial rhythm

Repeated distances, columns, blocks, gaps and scale ratios.

### Temporal rhythm

Cuts, holds, pulses, acceleration, pauses, repetition.

### Rule

Avoid random timing when the visual language implies measured structure.

## 9. Scale

Scale controls both hierarchy and physical impact.

### Poster logic

Very large type can become image; very small type can become texture.

### Realtime logic

Use scale changes as structural events rather than constant breathing on every element.

## 10. Contrast

Contrast can be:

- light/dark
- large/small
- dense/sparse
- static/moving
- sharp/soft
- geometric/organic
- saturated/desaturated
- regular/irregular
- wide/narrow

A composition becomes stronger when contrast is deliberate and limited to a few meaningful axes.

## 11. Balance

Balance is not always symmetry.

Types:

- symmetrical
- asymmetrical
- radial
- weighted by color
- weighted by scale
- weighted by density

### Realtime use

A moving focal point can continuously rebalance the composition while maintaining a designed center of gravity.

## 12. Tension

Tension comes from near-collisions, edge proximity, off-axis placement and scale differences.

### Rule

Tension should feel controlled. Accidental clipping and uncontrolled margin violations read as bugs, not expressive tension.

## 13. Grid systems

Grid options:

- single-column
- multi-column
- modular
- baseline
- hierarchical
- radial
- diagonal
- freeform over a hidden grid

### Realtime use

Grids can themselves animate, but the content should respond coherently when the grid changes.

## 14. Breaking the grid

Anti-grid composition works because a grid or structural expectation exists first.

### Rule

Break one or two relationships deliberately. If everything ignores alignment, there is no meaningful break.

## 15. Margins

Margins define the field of action.

### DC//LAB rule

Each sketch should define whether its edges are:

- safe
- bleed
- crop-enabled
- wraparound
- physically clipped by output hardware

Do not let this remain implicit.

## 16. Bleed and crop

Elements may intentionally extend beyond a frame.

### Realtime use

Expose crop/bleed behavior as a composition mode so it remains distinct from accidental overflow.

## 17. Density

Visual density controls energy.

### Realtime mapping

Audio amplitude, crowd data, touch count or simulation energy may alter density—but preserve global hierarchy and safe margins.

## 18. Layering

Layers can be organized by:

- depth
- opacity
- focus
- motion speed
- color role
- semantic role

### Rule

Every layer should have a reason to exist. Extra shader passes should not become visual clutter by default.

## 19. Color roles

Define semantic palette roles rather than raw color pickers:

- background
- foreground
- primary accent
- secondary accent
- warning/highlight
- muted/support

### Realtime benefit

A palette can change while preserving role relationships.

## 20. Luminance hierarchy

Color hue can vary wildly while luminance hierarchy stays stable.

### Realtime rule

Check the composition mentally or computationally in grayscale. If all important layers collapse into the same brightness, readability/hierarchy may be weak.

## 21. Saturation economy

Maximum saturation everywhere reduces emphasis.

Use saturation as a scarce resource.

## 22. Temperature

Warm/cool contrast can create depth and attention without changing brightness dramatically.

## 23. Color interaction

Colors change perceptually depending on surrounding colors.

### Realtime use

When palette backgrounds animate, foreground colors may need adaptive correction rather than static RGB values.

## 24. Image / type relationship

Common strategies:

- type over image
- type beside image
- type as mask
- image inside type
- type interrupting image
- image interrupting type
- shared grid
- deliberate collision

### Realtime rule

Choose a relationship model rather than stacking text over effects by default.

## 25. Poster composition

A poster often benefits from one dominant move:

- extreme scale
- asymmetrical anchor
- central image
- typographic field
- controlled crop
- repeated motif
- stark color contrast

### DC//LAB translation

Each sketch should ideally have one immediately recognizable visual proposition in a frozen frame.

## 26. Editorial pacing

Editorial systems manage sequence over pages; realtime systems manage sequence over time.

Translate:

- page turn → scene transition
- spread → keyframe/state
- section opener → major visual event
- caption → secondary live layer
- repeated folio → persistent status element

## 27. Information density

Not every moment should contain every parameter/value/message.

### Rule

Separate operator UI density from PROGRAM output density. PROGRAM should show only what belongs to the artwork.

## 28. Identity systems

A visual identity is a repeatable rule set, not a collection of one-off images.

Components may include:

- typography
- palette
- grid
- logo/mark
- image treatment
- motion grammar
- sound grammar
- transitions
- generative rules

### DC//LAB relevance

Future projects can expose a “visual system” object shared across multiple sketches or scenes.

## 29. Responsive identity

An identity may adapt to screen size, content, context or data while preserving recognizable invariants.

### Realtime rule

Define what is allowed to vary and what must stay stable.

## 30. Motion identity

Motion can be part of identity through recurring behaviors:

- reveal direction
- easing family
- acceleration profile
- repeat frequency
- morph logic
- type behavior
- camera behavior

### Rule

Do not choose easing independently for every effect.

## 31. Transition grammar

Transitions should belong to families.

Example families:

- cut
- wipe
- mask reveal
- zoom-through
- typographic morph
- dissolve
- displacement
- feedback smear

A future live mixer should let transitions themselves be designed assets.

## 32. Continuity

Motion feels clean when viewers understand what changed and what persisted.

### Realtime use

Maintain anchors between states: a word, color, axis, object or spatial region can persist while other elements transform.

## 33. Wayfinding logic

Wayfinding design prioritizes orientation, hierarchy and clarity across space.

### Installation relevance

For multi-screen work, define:

- primary display
- secondary/support display
- interaction zone
- audience approach direction
- readable distance
- feedback location

## 34. Spatial scale

What works on a 27-inch monitor may fail on a 6-meter projection.

Consider:

- physical viewing distance
- pixel pitch
- projection softness
- ambient light
- display brightness
- surface distortion

## 35. Materiality

Graphic design historically comes from physical processes: ink, paper, halftone, overprint, emboss, screenprint, photocopy, risograph, letterpress.

### Realtime opportunities

Simulate material logic rather than applying generic “grunge.”

Examples:

- ink spread tied to edge distance
- registration offset tied to print layers
- halftone based on luminance
- paper grain modulating absorption

## 36. Texture

Texture can establish material, depth or atmosphere.

### Rule

Texture should support hierarchy rather than flatten everything into equal noise.

## 37. Pattern

Patterns become systems when they have repeat rules, transformations and exceptions.

### Realtime use

Parameterize pattern family, cell, repeat, phase, interruption and response to interaction.

## 38. Symbol and icon systems

Icons need consistent:

- stroke weight
- corner logic
- bounding box
- optical size
- perspective
- fill/stroke relationship

This same discipline applies to generative symbol fields.

## 39. Data-driven design

Data should control a defined visual grammar rather than arbitrary parameters.

Example:

```text
data magnitude → density
category → palette role
confidence → opacity
change rate → motion intensity
```

## 40. Constraint as creativity

Strong generative work often comes from strict constraints.

Useful constraints:

- 2 colors
- 1 font family
- 1 grid
- 1 interaction rule
- fixed safe margin
- one motion family
- bounded noise

Complexity can emerge inside the system.

## 41. Controlled randomness

Randomness should have:

- seed
- range
- distribution
- spatial scale
- temporal scale
- correlation

### Rule

“Random” should never mean “unbounded.”

## 42. State design

Realtime graphics should define recognizable states:

- idle
- approach
- active interaction
- peak
- release
- recovery

This makes interaction legible and gives the work rhythm.

## 43. Feedback and response

Interaction needs visible causality.

A touch should create a response close enough in time and space that the viewer understands the relationship.

## 44. Simplicity and reduction

Removing an element is often a stronger design action than adding another effect.

Before adding an effect, ask whether hierarchy, scale, spacing or color can solve the problem first.

## 45. The frozen-frame test

Pause the sketch at several arbitrary frames.

Ask:

- does it still look composed?
- are margins controlled?
- is the focal hierarchy clear?
- is the palette balanced?
- does it look like a designed poster rather than an effect demo?

A strong realtime system should generate many strong still frames.

## 46. The extremes test

Test every artistic parameter at min/max values.

A designed system should not collapse when:

- density is maximum;
- type is widest;
- lens is largest;
- distortion is strongest;
- window is smallest;
- output is ultrawide/tall;
- pointer reaches edges;
- audio spikes.

## 47. The identity test

Could someone recognize the sketch from:

- one still frame?
- one motion gesture?
- one palette?
- one typographic behavior?

If not, the concept may still be too generic.
